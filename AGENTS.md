# 11vatedTech AI Game Jam Studio — Agent Operating Contract

This repository contains both the product specification and an executable local runtime foundation. It is not permission to claim the universal studio is complete. The runtime is v0.2.0; professional integrations are version- and capability-specific and remain uncertified until their conformance suites pass.

## Authority order
1. Safety, law, licenses, data protection and explicit human approvals.
2. `docs/00-foundation/MASTER_SYSTEM_CONTRACT.md` and quality bar.
3. Approved architecture decisions and security policies.
4. Domain-specific production pipeline and acceptance contract.
5. Convenience and agent preferences.

## Mandatory startup routine
1. Read `FREEBUFF_START_HERE.md`, `PROJECT_STATUS.md`, this file and current phase exit criteria.
2. Reconstruct the real repo, Git state, local configuration, database, adapter versions, application health and current evidence. Never treat old chat claims as current machine facts.
3. On Windows run `scripts/windows/bootstrap.ps1`, then `studio doctor`, `studio status`, `studio capabilities`, and the full tests. Do not install heavyweight applications, models, custom nodes, drivers or plugins without explicit approval.
4. Connect the local MCP server using `scripts/windows/mcp-config.example.json` with actual absolute paths. Confirm MCP initialize, tools/list and a safe status call before attempting project mutations.
5. Identify the next unclosed acceptance gate. Implement and verify that gate; do not respond with another high-level plan when a concrete task is available.

## Implementation doctrine
- Reuse and pin mature professional implementations. Inspect source, releases, license, issues, security and compatibility before adoption. Distinguish `RESEARCHED`, `INSPECTED`, `REPRODUCED`, `INTEGRATED`, `VALIDATED`, and `CERTIFIED`.
- Preserve provider neutrality. Freebuff remains the reasoning coordinator; this runtime supplies persistence, policies, tools, evidence and local operations. It must not become a proprietary model dependency.
- Use typed operations and native application APIs. Prefer semantic edits and read-back postconditions over GUI coordinates or free-form scripts.
- Never use primitive geometry, SVG or canvas as a final visual deliverable. Temporary technical scaffolding is allowed only when it is explicitly internal and never misrepresented as final art.
- Never claim an output is commercial quality because generation completed or a file exists. Verify source, native structure, imports, actual rendered/runtime context, craft rubric and performance.
- Do not commit model weights, large media, private assets, credentials, caches, derived output or user project source without an explicit reason and rights review.
- Do not execute arbitrary shell commands. Prefer typed adapter operations. The runtime uses argv arrays, never `shell=True`; Blender Python and Godot editor execution are still powerful code execution and require human approval.
- Never weaken permission policy to make a test pass. Never let an agent approve its own approval request.
- One agent owns a mutable project region at a time. Avoid concurrent edits to the same scene, graph, timeline, source file or artifact.
- Do not delete, overwrite, publish, install or transmit without narrow approval. Make backups and use a duplicate/worktree before changing user-owned projects.

## Required evidence for every meaningful deliverable
- Intent/requirement IDs and acceptance matrix.
- Tool/application and exact version/revision.
- Inputs and source references with license/provenance.
- Reproducible workflow or commands and configuration.
- Output file(s), native editable source and SHA-256 manifest.
- Application import/read-back and runtime evidence.
- Automated test report, logs, screenshots/renders/captures and resource metrics.
- Visual/audio/craft review with defects and revisions.
- Known limitations, reviewer, verdict and exact support matrix.

## Status taxonomy
`NOT_STARTED`, `RESEARCHING`, `DESIGNED`, `IMPLEMENTING`, `INTEGRATING`, `TESTING`, `BLOCKED`, `VALIDATED`, `CERTIFIED`, `DEPRECATED`.

A tool or feature may be marked `CERTIFIED` only after 100% of its mandatory acceptance suite passes on a named OS/application/driver/model support matrix, no open P0/P1 defects remain, licensing/security are approved and evidence is retained. Certification is never universal by implication.
