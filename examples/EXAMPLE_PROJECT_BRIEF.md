# Example Project Brief — Illustrative Only

This example demonstrates how Freebuff should structure a deliberately incomplete request. It is not a committed product direction.

## Original intent

“Make a short atmospheric exploration game about an abandoned observatory. I want it to look beautiful, feel mysterious, and have a memorable interaction.”

## Intent expansion

- Audience/platform: unknown; assume single-player desktop prototype until confirmed.
- Core experience: exploration, environmental storytelling, one signature interaction, short completion arc.
- Visual direction: define a distinctive art bible before choosing generation methods. Candidate directions should be compared rather than defaulting to generic sci-fi.
- Audio: environmental ambience and a small music identity.
- Accessibility: readable UI/subtitles, remappable controls if scope warrants.
- Scope: one complete playable area; no assumed multiplayer or progression meta-system.

## Proposed acceptance criteria

- Launch to menu or clear start state.
- Player can navigate the area with consistent camera/control behavior.
- At least one deliberate environmental interaction changes game state and produces visual/audio feedback.
- Environment contains original, integrated assets with source files and provenance.
- Visual style is consistent across environment, interaction object, UI and effects.
- Audio is present and mixed for the target device.
- Completion state is reachable and tested.
- Build runs from a clean output directory.
- Evidence includes art bible, asset manifests, runtime captures, test report and build hash.

## Open decisions

Target engine/platform, exact art direction, input scheme, accessibility expectations, target length and acceptable compute/time budget. Ask only if these decisions materially affect the first prototype; otherwise document provisional assumptions.
