## PR #2 review fixes, cycle 1 (committed as `1b387c3`, CI 6/6)

A second `-i`, `-y`, protocols, maps, filter scripts, or bare paths are rejected with `ValidationError` before any process launches; argv is still executed without a shell.
2. **Cancellation/recovery race (jobs.py)** — cancelling a RUNNING job enters non-terminal `CANCELLING` (unstarted jobs go straight to terminal `CANCELLED`; double-cancel raises). The task boundary applies terminal `CANCELLED`; `run()` no longer short-circuits so a crash-after-cancel quarantines RUNNING tasks to `NEEDS_RECONCILIATION`; a cancel that lands during the final task wins over the success aggregation. Schema (`schemas/job.schema.json`), lifecycle doc, and `PROJECT_STATUS.md` describe `CANCELLING`.
3. **Godot evidence overwrite (service.py)** — `_godot_inspect` writes a unique `godot-inspect-<uuid12>.json` per invocation (mirroring the Blender inspector), so `FileAccess.WRITE` truncation can no longer destroy earlier evidence.

## PR #2 review fixes, cycle 2 (this change set, on top of `1b387c3`)

Second-round review found two residual TOCTOU windows (startup claim, final aggregation) plus stale docs. All addressed on the existing branch:

1. **Atomic cancellation transitions (jobs.py)** — every job-status write on the cancel path is now a single-statement compare-and-swap guarded by `rowcount`, so the precondition is evaluated at write time:
   - `cancel()` itself is two CAS UPDATEs (`RUNNING → CANCELLING`, else any-live → `CANCELLED`); a lost race falls through to a fresh read that reports the true state, and the status read-back happens on a new connection after commit. Terminal/cancelling/unknown states keep their exact previous errors.
   - Startup claims execution via `_claim_running()`: one guarded `→ RUNNING` UPDATE. A cancel landing after the entry read can no longer be overwritten — the write does not apply, and the runner returns terminal `CANCELLED` (never-started) or converts `CANCELLING` at the first task boundary with zero attempts.
   - The completion shortcut and the final aggregation apply `SUCCEEDED` only through a guarded write; when the guard refuses, the winner is a concurrent cancel and terminal `CANCELLED` is applied instead. Task-state reads need no guard (`cancel()` never touches tasks). The mid-run boundary write is guarded to `CANCELLING`-only.
2. **Barrier-based race tests (2, both event-ordered, no sleeps)** — `test_cancel_in_startup_window_never_executes` parks the worker between the entry read and the claim write, cancels exactly in that window, and asserts `CANCELLED` with zero attempts; `test_cancel_between_final_read_and_write_never_reports_succeeded` holds the worker inside the final task, cancels past its last status read, and asserts the aggregation yields `CANCELLED` with the finished task honestly `SUCCEEDED`. Worker failures surface via a shared list, hooks are always restored, threads are joined.
3. **Docs reconciled** — `PROJECT_STATUS.md` snapshot moved to 2026-11-06: 184/3 suite result, packaged build marked produced with its evidence path, DAG row no longer says cancellation is unimplemented (it describes the CAS design), skips row covers all three environment-dependent skips.
