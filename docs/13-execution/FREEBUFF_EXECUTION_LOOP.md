# Freebuff Execution Loop — Detailed Operational Standard

## Phase A: reconstruct

Inspect filesystem and git tree, active branch, commit, uncommitted changes, `PROJECT_STATUS.md`, task evidence, runtime home, SQLite records, policy file, application versions and active processes. Capture time and command output. Never overwrite unknown user content.

## Phase B: intent completion

Turn user language into a structured creative/technical brief:
- audience, platform, genre/discipline, format and delivery target;
- purpose, user experience and emotional/functional outcomes;
- references with source/license and what design principles to learn;
- explicit must-haves, must-not-haves and constraints;
- scope split into deliverables and dependencies;
- assumptions register with confidence and owner;
- acceptance matrix mapping every requirement to a test and evidence item;
- risk, cost, hardware and permission plan.

Ask only when an unknown is genuinely blocking or a permission/approval is required. Otherwise state a conservative assumption and proceed reversibly.

## Phase C: professional research and selection

Search professional products, GitHub, standards, papers and official docs. Inspect pinned code. Capture exact repository URL, commit/tag, last release/date, license, OS support, dependencies, API, test coverage, maintenance, vulnerabilities, cost, cloud dependence, offline behavior, VRAM/RAM and output ceiling. Compare candidates on the target task. Record adoption decision and a reproduction plan.

## Phase D: art/engineering direction

Before production, generate discipline-specific design documents. For visual work: references, style thesis, silhouette, shape language, composition, palette, lighting, material response, texture density, typography, motion and camera language. For software: architecture, modules, data contracts, test strategy, error behavior, security, performance and deploy target. For audio/video/CAD/research, define their domain-specific standards and deliverable structure.

## Phase E: plan the production graph

Create typed tasks. Each declares capability, dependencies, inputs, output artifact contracts, side-effect class, approval, timeout, resource needs, idempotency, completion predicate, retry policy, checkpoints, verification and rollback. Avoid two tasks mutating the same artifact concurrently. Use one owner per mutable application object/project region.

## Phase F: manufacture

Use professional native applications and semantic APIs. Prefer existing mature pipelines. Keep editable sources and deterministic exports. Preserve exact workflows, random seeds where relevant, model versions, prompts, application versions, settings, source references and licenses. Do not hide structural problems by adding more visual noise/detail.

## Phase G: integrate and inspect

Import into the actual target application. Read back object/resource/scene/component state. Verify scale, transforms, dependencies, textures, color spaces, materials, rig/animation, sound routing, timeline structure, UI scaling and other discipline-specific properties. A file that merely exists does not pass.

## Phase H: test and critique

Run unit, schema, adapter, integration, runtime, performance, compatibility and security tests as appropriate. Capture fixed-condition screenshots/renders/video/audio. Assess at native target resolution/distance/speed. Use automated reviewers as defect triage only until calibrated. For subjective high-impact deliverables, include qualified human review.

## Phase I: root-cause repair

Every defect needs a location, severity, reproduction steps, evidence, hypothesized cause and assigned upstream stage. Fix topology issues in modeling, texture stretch in UV/layout, bad contact in rig/animation, composition in camera/layout, integration errors in importer/settings—not merely by masking symptoms. Re-run targeted and regression tests.

## Phase J: delivery and learning

Package the native source and runtime deliverable; produce manifests, license/provenance ledger, test report, review report, known limitations, support matrix and reproducibility recipe. Update validated Skills and benchmark corpus only from evidence-backed outcomes. Keep failure examples for regression learning.
