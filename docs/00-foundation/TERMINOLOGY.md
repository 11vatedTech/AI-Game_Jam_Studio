# Terminology

- **Capability:** A named, versioned outcome the studio can perform with defined inputs, outputs, prerequisites, permissions, tests, and support level.
- **Adapter:** A bounded integration that exposes an application's or service's capabilities through studio contracts.
- **Skill:** Reusable domain knowledge and procedure that guides planning and tool use; a Skill is not proof that the connected tool works.
- **Workflow/recipe:** A versioned multi-step production procedure with dependencies, checkpoints, and acceptance criteria.
- **Agent role:** A constrained responsibility (e.g. art director, technical artist, gameplay engineer). Roles may be prompts/configurations rather than separate long-lived processes.
- **Artifact:** A produced file, project, build, media item, dataset, report, or other deliverable with lineage and validation state.
- **Evidence:** Inspectable proof attached to a requirement or quality claim.
- **Support matrix:** Exact operating systems, application versions, hardware profiles, formats, and configurations covered by validation.
- **Certified capability:** A versioned capability that has passed all mandatory tests and governance checks for its declared support matrix.
- **Visual moat:** The ability to produce distinctive, coherent, contextually validated, professional-quality visual work.
- **Production moat:** The compounding integrated system that moves from incomplete intent to verified finished deliverables.
- **Blockout:** Temporary composition/scale/flow prototype; not a final deliverable unless the task explicitly asks for a blockout.
- **Golden artifact:** A known-good output retained for regression comparison with its source, version, and reproduction instructions.
- **Quality gate:** A required condition that blocks progression or release when not satisfied.
- **Human approval:** Explicit authorization by an appropriately empowered person for a consequential action or subjective release judgment.
